# 工作规则

## 写代码时必用 skill

**每次写代码前，先加载这两个 skill：**

1. **`ponytail`** —— 最懒但能用的方案优先
   - 先问「这功能需要存在吗」，不需要就跳过
   - 优先复用本仓库已有的 helper / 类型 / 模式
   - 标准库 → 原生特性 → 已装依赖 → 一行 → 才自己写
   - 最小 diff、最少文件、能删就删
   - 修 bug 修根因不修症状（grep 所有调用方）
   - 非常规逻辑留一个最小可运行的自检

2. **`karpathy-guidelines`** —— 少犯 LLM 常见错
   - 想清楚再写，不假设、不藏困惑，有歧义就问
   - 最简实现，不加没要求的功能/抽象/配置
   - 外科手术式改动，只碰必须碰的
   - 把任务变成「可验证的目标」，循环直到验证通过

**用法：** 动代码前 `skill({ id: "ponytail" })` + `skill({ id: "karpathy-guidelines" })`。
两个都属"治理怎么写代码"，与怎么说无关——代码优先，解释从简。
